# C86 USB 펌웨어 업데이트

최초 한 번은 C86 양쪽에 영구 부팅부를 SWD로 기록합니다. 이 문서는 이후 앱 업데이트 절차를 설명합니다. 현재 검증 기준은 왼쪽 v0.3.23, 오른쪽 v0.3.20입니다. 실물 전원 차단 복구 시험은 별도입니다.

## 최초 설치

0.1 / 0.2 펌웨어에는 이 업데이트 부팅부가 없습니다. **새 C86은 양쪽에 부팅부와 앱을 SWD로 한 번 설치**해야 이후 앱을 USB로 바꿀 수 있습니다. 이번 연결된 양쪽은 이미 완료했으므로 일반 앱 업데이트를 위해 반복하지 않습니다. 기존 펌웨어가 `BAD_COMMAND`를 반환하면 USB 재시도를 반복하지 말고 최초 SWD 설치 여부를 확인하세요. 최초 SWD 기록은 별도 명시적 실행 단계입니다.

이후 앱 업데이트는 왼쪽 PC용 USB로 진행합니다. 오른쪽은 PC에 직접 USB를 연결하지 않고 왼쪽–오른쪽 통신 케이블을 유지합니다. 우측에 전원이 정상 공급되어야 합니다. 이 프로토콜로 부팅부 자체를 덮어쓰지는 않습니다.

## 업데이트 전

1. Studio에서 보정·매핑·RT 등 필요한 RAM 설정을 먼저 **키보드에 저장**하세요. 업데이트 도구는 자동 SAVE를 보내지 않습니다.
2. Studio의 연결을 종료하고 다른 MCP/Python HID 클라이언트도 닫으세요. 브라우저는 Studio와 같은 Web Lock을 사용하지만 브라우저와 Python 간 잠금은 공유되지 않습니다.
3. 올바른 좌우 `.fw.json` 파일을 준비하세요. 기본 C86 파일은 `build/c86/left/c86-left-app.fw.json`, `build/c86/right/c86-right-app.fw.json`입니다. 16kHz 복구 후보는 `build/c86/scan16k/{left,right}/`에 생성됩니다.
4. 업데이트 중 PC USB와 좌우 전원을 유지하세요. 저장 설정 영역(sectors 6/7)은 보존하지만 **저장하지 않은 RAM 설정은 재시작 시 사라집니다.**

## 브라우저

Studio의 프로필 탭에서 **C86 USB 펌웨어 업데이트**를 열거나 로컬 서버의 `/update.html`로 이동합니다.

- 좌우 정식 릴리스를 불러오거나 같은 버전의 좌우 파일을 함께 선택합니다. 두 파일의 CRC32·SHA256과 앱 내부 하드웨어·역할·버전을 검사합니다.
- **연결 + 양쪽 확인**으로 실제 보드의 하드웨어, UID, 부팅부, Flash 용량을 확인합니다. 오른쪽을 확인하는 동안 왼쪽은 중계 모드로 전환됩니다.
- 동의 체크 후 **좌우 업데이트**를 누르면 오른쪽부터 기록합니다. 이미 같은 이미지가 실행 중이면 건너뜁니다.
- 장치가 전체 앱 CRC를 검증하고 커밋한 뒤 INFO의 버전·크기·CRC·UID를 대조합니다. 선택한 경우 전체 Flash를 추가로 읽어 파일과 바이트 단위로 대조합니다. 검증 후 새 앱을 실행하고 다시 확인합니다.
- 양쪽의 버전과 CRC를 확인한 뒤 중계 모드를 종료합니다. 장치를 확인만 했다면 **왼쪽 업데이트·중계 모드 종료**를 누르세요.

## CLI

패키지 검사만 수행하며 USB를 열지 않는 명령:

```powershell
.venv/Scripts/python.exe -m host.update_firmware --package build/c86/left/c86-left-app.fw.json
```

실제 쓰기는 명시적 `--write`, 왼쪽 HID의 정확한 serial, 대상과 파일이 모두 필요합니다. 아래 명령은 예시이며 실제 최초 설치와 쓰기 허가를 대신하지 않습니다.

```powershell
.venv/Scripts/python.exe -m host.update_firmware --package build/c86/right/c86-right-app.fw.json --target right --serial SERIAL --write --full-readback
```

중계 모드 종료만 요청하는 명령:

```powershell
.venv/Scripts/python.exe -m host.update_firmware --serial SERIAL --exit-maintenance
```

## 오류·중단 후

BEGIN·WRITE·COMMIT은 타임아웃이 나더라도 자동 재전송하지 않습니다. 장치가 이미 처리했는데 응답만 유실됐을 수 있기 때문입니다. 기존 기록 세션은 USB 연결 종료만으로 사라지지 않습니다.

앱↔부팅부 전환의 ENTER/RUN도 한 번만 전송합니다. 재열거 중 이전 HID핸들이 잠시 다시 보이거나 ACK가 유실되면 제한 시간 안에서 연결을 다시 열고 INFO로 같은UID·역할·모드를 확인합니다. 이 읽기·재연결 재시도는 Flash 삭제·기록 명령 재전송과 다릅니다.

**기록이 시작된 뒤 실패했다면 모든 보드 전원을 완전히 분리했다가 다시 연결한 후 새로 명시적으로 시작하세요.** 별도 프로그래머 등으로 우회 공급되는 전원도 남아 있지 않아야 합니다. 재시도는 처음부터 앱을 삭제하고 기록합니다. 이전 세션이 남아 있으면 도구가 새 BEGIN 전에 중단합니다.

메타데이터가 유효하지 않은 앱은 실행하지 않고 부팅부에서 대기하도록 설계했습니다. 이는 자동 롤백이 아니며 이전 앱 사본을 보관하지 않습니다. 복구는 정상 부팅부와 전원·USB/좌우 통신이 유지되는 조건에 의존합니다. 실물 전원 차단 시험은 별도로 필요합니다.

## 성능 카운터

새 앱의 읽기 전용 측정 명령은 다음과 같습니다. 자동으로 실행되지 않습니다.

```powershell
.venv/Scripts/python.exe -m host.performance --serial SERIAL --seconds 5
```

실제 USB DataIn 완료 카운터와 ADC 시퀀스 변화량을 장치 시간으로 나눕니다. 32비트 카운터·시간 랩어라운드를 처리하고, 오류/오버런/늦은 IRQ 증가량을 함께 표시합니다. 최소·최대 스캔 주기와 최대 IRQ 실행 시간은 부팅 후 누적 극값이며 측정 구간만의 값이 아닙니다. CPU 240MHz를 기준으로 시간을 환산합니다.

이 카운터만으로 USB 버스 전송, Windows 수신율 또는64kHz 센서 정확도를 증명하지 않습니다. 이번v0.3.3은 별도ETW에서Windows USB 완료7,995.8Hz를 확인했습니다. 이것도 변하지 않은 보고서를 포함하며 실제 키→화면 지연이나 전선 토큰 타이밍을 측정한 것은 아닙니다.

v0.3.2부터 읽기 전용0x41은 정상 S7 링크의 poll/accepted/timeout/순번/늦은 응답/UART/TX/CRC/framing 카운터와 누적RTT 범위를 제공합니다. 기존0x40의52바이트 USB/ADC 응답은 유지합니다. `host.performance.measure_link()`는0x41 두 번만 조회하며 SAVE·OUTPUT·업데이트 명령을 보내지 않습니다. 업데이트의 C7 중계 성공과 정상 S7의8kHz 유효 응답률을 분리해 판단합니다.
